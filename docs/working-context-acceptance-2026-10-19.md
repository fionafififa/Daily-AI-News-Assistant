# 按状态重建新闻工作上下文

日期：2026-10-19（Asia/Shanghai）。修改位于用户实际 D 盘项目；`.env` 未修改。

## 实现范围

这是模型调用前的工作材料整理，不是来源获取前的候选预筛。首次获得的候选全部保留，LLM 自行决定去留、是否补读原文、工具顺序和结束时机。

- 新增 `record_article_states`，由模型批量记录 `pending`、`to_read`、`selected`、`excluded` 与原因；入选项附 1–3 段精确原文证据，程序校验后接受。
- `WorkingContextMiddleware.awrap_model_call` 在每次请求前调用 `rebuild_messages`，通过 `request.override(messages=...)` 发送请求副本。保留原任务、工具调用 ID、调用与返回的配对、工具错误及其他工具内容。
- 将新闻工具的旧长返回替换成简短回执，按当前状态生成当轮唯一工作清单：未决和待阅读材料保留当前全文，排除项只保留 ID/标题/理由，入选项保留证据、出处与独立日期。
- `read_article` 可重新打开入选/排除项为 `to_read`；已有原文复用本次任务缓存，恢复完整材料后由模型重新判断。服务器不会因为状态为待阅读就自动替模型执行工具。
- 图内原始消息不变；`data/materials/<run_id>.json` 保存完整 RSS 摘要、已读原文、状态与阅读记录，`<run_id>-context.jsonl` 保存每轮字符统计。原工具执行日志保留。
- 默认 `WORKING_CONTEXT_ENABLED=true`，`.env.example` 和 README 已说明。

## 验证

64 项测试通过；Ruff 检查和格式检查通过。新测试直接捕获 `ChatOpenAI` 的 HTTP 请求，验证两种由模型选择的工具顺序、排除长文移除、未决材料保留、入选证据保留、重新打开全文、错误反馈、工具 ID 配对及服务器归档。40 篇合成材料回放：清单从 204,939 字符降至 9,141 字符（减少 95.54%）。合成回放不是实际新闻或 API Token 测量。

真实模型 `deepseek-flash` 验收成功：42 篇真实候选，最终 36 篇排除、5 篇入选、1 篇保持未决，5 条简报通过复核并已推送到独立验收收件箱。未决文章未被自动排除或删除。实际请求回调确认每轮至多一份工作清单，排除项的长文均未进入清单。入选证据与服务器完整原文匹配。报告中的应用源码哈希与最终文件一致。

## 试跑中发现并处理的已有复核边界

1. `$20 million` 与 `2000 万美元` 应按同一数量比较；同时支持常见 K/M/B 规模与中文万/亿的换算，错误数量仍拒绝。
2. “最高实测 59.2/100”不能变成“指标上限 59.2”；补充提示和确定性拦截，防止此前满分问题换一种说法出现。
3. 模型引用可能遗漏原文 `$` 或 `**` 等字符。引用校验保持严格；格式/引用/数值校验失败最多允许一次修正请求，只重试最终摘要复核，不重跑研究。明确证据不足直接失败，两次均未通过不推送。

中间试跑记录保留：124424Z 因单位换算误拦截失败；125051Z 虽完成推送，但人工检查发现 PRIME 的“指标上限”措辞，不能作为该内容问题通过的证据；125514Z 因引文不连续被正确阻止推送。以上记录未改写为通过。这三次试跑 API 已返回用量合计 393,003 Token，属于调试成本，不计入本次成功运行用量。
